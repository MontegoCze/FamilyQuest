# FamilyQuest

FamilyQuest is a gamified family task manager for parents and children. This repository is organized as a monorepo for the initial Phase 1 implementation.

## Project structure

- `backend/` – FastAPI application, SQLAlchemy models, auth, and API routes
- `database/` – Alembic migrations and relational database scripts
- `frontend/` – React + TypeScript client scaffold
- `docs/` – design and architecture notes

## Delivered

- JWT authentication with parent/child roles and secure family scoping
- Family and child management (including deactivation)
- Task CRUD, child assignments, completion review, and 1–5 star ratings
- XP transactions, levels, streaks, achievements, and a family leaderboard
- Rewards, XP-backed redemption requests, parent approval, and notifications
- Responsive Czech-language parent/child dashboard with API integration

## Quick start

### 1) Backend

```bash
cd backend
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy ..\.env.example .env
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

### 2) Frontend

```bash
cd frontend
npm install
npm run dev -- --host 0.0.0.0 --port 5173
```

## API

Base URL: `http://localhost:8000/api/v1`

Available routes:

- `POST /auth/register`
- `POST /auth/login`
- `GET /me`
- `GET /family`
- `POST /family`
- `POST /family/children`
- `GET|POST /tasks`, `PATCH|DELETE /tasks/{id}`
- `POST /tasks/{id}/assign`, `POST /tasks/{id}/complete`
- `GET /completions`, `POST /completions/{id}/review`, `POST /completions/{id}/rate`
- `GET /stats`, `/leaderboard`, `/achievements`, `/rewards`, `/redemptions`
- `GET /adventure` for the family map; parents can `POST|PATCH|DELETE /adventure/points`
  and reorder points with `POST /adventure/reorder`
- `GET /notifications` and notification read endpoints

## Default demo accounts

After registration, use the created email and password. Phase 1 does not ship pre-seeded users automatically, but the app is ready for the registration flow.

## Notes

- The default database URL is SQLite for ease of local development.
- Render uses the existing PostgreSQL database configured in the API service's `DATABASE_URL`; local development continues to use SQLite by default.

## Deployment on GitHub + Render

The repository includes [`render.yaml`](./render.yaml), which defines:

- `familyquest-api` – FastAPI Web Service
- `familyquest-web` – React Static Site

1. Push this existing repository to GitHub.
2. In Render select **New > Blueprint** and connect the GitHub repository.
3. Render will create or update the API and static site from `render.yaml`. Set `DATABASE_URL` on the API to the existing Render PostgreSQL database's **Internal Database URL**.
4. If you use a custom frontend domain, update `BACKEND_CORS_ORIGINS` on `familyquest-api` to a JSON array containing that exact `https://` URL.
5. Redeploy the API after changing environment variables.

The API runs Alembic migrations before startup. `SECRET_KEY` is generated by Render; do not commit production secrets. The frontend receives the API URL through `VITE_API_URL` at build time.

To enable email invitations, configure these API environment variables in Render:
`SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM_EMAIL`, and
`FRONTEND_URL`. The SMTP password must be stored only as a secret environment
variable.

The repository pins Render's Python runtime through `.python-version` because the backend dependencies are tested on Python 3.13.
